# LESSONS.md — セッション横断の教訓集

> 読み方：タスク開始時に「一般化」の行だけでも流し読みする。
> 書き方：失敗を解決した直後・セッション終了時に3〜5行で追記（形式は `.claude/skills/kaizen-loop.md` 参照）。

---

## 2026-07 WordPressがコンテンツ内の script を無効化する
- 状況: 診断ツール（JS入りページ）をREST API経由で固定ページ化したら、質問が表示されなかった
- 誤り/罠: WPの表示パイプライン（wpautop・サニタイズ）がscriptを壊す。管理画面からは原因が見えない
- 正解: JSが必要なページはWordPressの外に出す（`static/` の独立HTML＋ConoHaファイルマネージャーで配置）
- 一般化: プラットフォームのコンテンツ処理層と2回戦って負けたら、その層の外に出る設計を検討する

## 2026-07 ConoHa WAFはscriptタグ入りのAPI投稿を403にする
- 状況: script入りページを `wp_draft.py push` したら 403 Forbidden
- 誤り/罠: 認証エラーと誤解しやすいが、実際はWAFのXSS誤検知
- 正解: WAF OFF → push → WAF ON。もしくは静的HTML化でAPI自体を通さない
- 一般化: 403は「認証」より先に「WAF/セキュリティ層の誤検知」を疑う。攻撃ログ画面で確認できる

## 2026-07 Windows側の未コミット変更が毎回pullを失敗させる
- 状況: ユーザーのローカルに生成画像・改行差分が溜まり、pullのたびにstash儀式が必要になった
- 誤り/罠: stash→pull→popはコンフリクトを生みやすく、初心者には負担が大きい
- 正解: ローカル成果物（画像等）は一度コミットさせて双方向を同期。以後はpull一発になる
- 一般化: 「毎回同じ回避手順」が発生したら、回避ではなく原因（未コミット資産）を解消する

## 2026-07 マージコンフリクトのマーカーがYAMLを壊す
- 状況: stash popでコンフリクトしたmdをそのままpushしたら frontmatter パースエラー
- 正解: `git checkout --ours <file>` で採用側を確定 → wp_id等の失われたメタは手動で復元
- 一般化: パースエラーの前に「コンフリクトマーカー残留」を疑う（`<<<<<<<` をgrep）

## 2026-07 push先カテゴリがWP側に無いと一括pushが大量失敗する
- 状況: push-missingでAI記事46本が「カテゴリが見つかりません: ['ai']」で失敗
- 正解: 先に `init-categories`（冪等）でカテゴリを作成してから再実行。再実行安全な設計だったので被害ゼロ
- 一般化: 一括処理は「前提リソースの存在確認」を先にやる。道具は再実行安全（冪等）に作っておくと失敗が怖くない

## 2026-07 div内のMarkdownは変換されない（python-markdown）
- 状況: `<div>` で囲んだ表・太字がそのまま文字列で表示された
- 正解: 装飾divの中は生HTMLで書く。またはMarkdown変換後にラップする仕組み（frontmatterの body_class）を使う
- 一般化: 変換パイプラインに入れる前に、本番と同じ変換をローカルで再現して確認する（推測しない）

## 2026-07 CSSは「追加CSS」貼り付け運用（子テーマ未デプロイ）
- 状況: cocoon-child/style.css はサーバーに未配置。WordPressの 外観→カスタマイズ→追加CSS に全文貼り付けで運用中
- 罠: style.cssを変更したら、ユーザーに「追加CSSへの貼り直し」を依頼する必要がある（pushでは反映されない）
- 一般化: 反映経路が非自動の資産は、変更時に必ず反映手順込みで案内する

## 2026-07 セレクタの広い当てすぎで無関係要素が壊れる
- 状況: `.lp-page table th` の紺背景がCocoonの目次(.toc)にも当たり、目次が読めなくなった
- 正解: 影響範囲を確認して除外(:not)か非表示を選ぶ。LPでは目次自体を非表示にした
- 一般化: ページ全体スコープのCSSを書いたら、テーマが同スコープに注入する要素（目次・シェアボタン等）への影響を確認する

## 2026-07 診断LPの主要な設計判断（再利用可）
- URL共有型の状態保存: 回答をクエリ(?r=a_b_c_d)にエンコード→ブックマークで結果復元。サーバー不要
- 差し替え前提の設計: アフィリURLは AFF オブジェクトに集約、表示順は recommend() の配列順
- 広告コンプラ: PR表記・rel="nofollow sponsored"・noindex・補助金は「可能性」表現、を最初から組み込み
- 一般化: 「あとで差し替わるもの」は必ず1箇所に集約し、★コメントで編集ポイントを明示する
