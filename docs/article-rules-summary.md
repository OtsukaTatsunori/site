# 記事作成ルール総集（横展開用）

このドキュメントは、当サイトの記事作成に関するすべてのルール・ガイドラインを1ファイルにまとめたものです。
新しいカテゴリを立ち上げる際に、このファイルをベースにしてください。

## 1. サイトのミッション

> **「大人が学びなおしで失敗しないための、ひとつめに読む場所」をつくる。**

解決する課題：
- 情報が多すぎて選べない
- 料金体系が複雑
- 自分に合うか不安
- 補助金を知らない

5. **期待を超える情報を渡す** — 読者が気づいていなかった重要情報まで届ける

10. **専門用語は伝わる形に直す** — やさしい言葉で説明してから正式名称

## 4. タイトルの付け方

- **文字数**：32文字前後
- **メインKWは左寄せ**
- **数字を入れる**：「7選」「5つの理由」
- **ベネフィットを明示**：「最短で」「初心者でも」
- **年号を入れる**：「【2026年】」

### テンプレート
```
比較記事: 【2026年】{KW}おすすめ{N}選｜{特徴}を徹底比較
レビュー: {サービス名}の評判・口コミは？{特徴}を徹底レビュー【2026】
How-to:  {KW}｜{誰が}{何を}するための{N}ステップ
悩み解決: {悩み}で困っている人へ｜{解決策}を解説
```

## 6. 記事構成テンプレート

### 比較・ランキング記事
```
導入（共感＋結論先出し＋この記事でわかること）
H2: 選び方のポイント（3つ）
H2: おすすめランキングTOP N（各：特徴・料金・メリデメ・向いている人・CTA）
H2: 比較表でまとめて確認
H2: 目的別おすすめ
H2: よくある質問（FAQ）
まとめ（要約＋TOP3再掲＋CTA）
```

### レビュー記事
```
導入（一言紹介＋結論＋この記事でわかること）
H2: 基本情報
H2: 良い評判・口コミ
H2: 悪い評判・口コミ
H2: 実際に使ってみた体験レビュー ★重要

H2: こんな人におすすめ / 向かない
H2: 始め方（手順）
H2: FAQ
まとめ（総評＋CTA）
```

### 情報・How-to記事
```
導入（共感＋結論先出し）
H2: 基本知識

H2: おすすめサービスN選
H2: よくある失敗例と対策
H2: FAQ
まとめ（要約＋次にやるべきこと）
```

## 7. ライティングルール

### 文体
- **です・ます調で統一**
- 一人称は「当サイト」
- 読者への呼びかけは「あなた」または「◯◯の方」

### 一文ルール
- **60文字以内**
- 主語と述語を近くに
- 一文に複数情報を詰め込まない

### PREP法
- **P**oint（結論）→ **R**eason（理由）→ **E**xample（具体例）→ **P**oint（再結論）

### 読みやすさ
- 漢字:ひらがな = 3:7
- 2～3文で1段落
- 3つ以上の項目は箇条書き
- 重要箇所は**太字**

## 8. 人間らしさの追加要素

各記事に最低2個ずつ入れる：

| ブロック | 用途 |
|---|---|
| 💬 **現場の本音** | 実務者視点のリアルな意見 |
| 💡 **プロのひとこと** / **コツ** | 実践的なアドバイス |
| ⚠️ **注意** / **重要** | 気をつけるべきこと |
| 📝 **ここがポイント** | 特に重要な情報 |

## 9. SEO実装ルール

### KW配置（必須箇所）
- タイトル（左寄せ）
- メタディスクリプション
- 冒頭100字以内
- H2見出しの複数箇所
- 画像のalt属性
- まとめ部分

### 内部リンク
- 1記事あたり5～7本
- アンカーテキストにKWを含める
- トピッククラスター型で設計

### 見出し
- H1は1つだけ
- H2は5～10個
- 階層構造を守る（H2→H3→H4）

### FAQ構造化データ
- `### Q.` パターンで書く → `wp_draft.py push` 時に自動でJSON-LDが挿入される

## 10. 画像ルール

- **モバイル最適化**：幅800px、フォント最小18px、1カラム
- **alt属性**：日本語でメインKWを含める
- **ファイル名**：英語（WordPress URLに使われる）
- **ファイルサイズ**：200KB以下
- **スクショ必須の記事は作らない**（自動生成できないため）
- データ駆動の図解・比較表・フロー図のみ使用
- スクショ必須でスキップした記事は必ず一覧で報告

---

## 11. アフィリエイトルール

### 配置（3箇所）
1. 記事冒頭の結論付近
2. 本文中の適切な箇所
3. まとめの直前

### CTAの3要素
1. ベネフィット（何が手に入るか）
2. 簡単さ（かかる時間）
3. 行動（何をすべきか）

### ステマ規制対応
- ファーストビューに「アフィリエイト広告を利用しています」を表示

## 12. 法的リスク回避

| 項目 | ルール |
|---|---|
| 確定申告 | 「給与所得者は副業の所得が年間20万円超で所得税の確定申告が必要。住民税は金額にかかわらず申告が必要。詳細は税務署に確認を」 |
| 会社バレ | 「リスクを軽減できるが完全には防げない」（断定しない） |
| 収入目安 | 「当サイト調べの参考値であり、収入を保証するものではありません」 |
| 著作権 | AIツールの著作権は「法的に未確定な部分がある」と明記 |
| 年収 | 「経験者を含む市場相場。未経験からの転職直後は下限以下が一般的」 |

### 使ってはいけない表現
- 「絶対」「必ず」「誰でも」「確実に」
- 「稼げる」「成功する」（根拠なしに）
- 「最高」「最強」「究極」（誇大表現）

## 13. カニバリ回避ルール

- 新記事を書く前にcontent-planでKWの重複を確認
- 既存記事と同じKWをメインにしない
- 深掘り記事は既存記事の3～4倍詳しく書く
- 公開後はステータスを更新

---

## 14. 品質基準（公開してよい記事の最低ライン）

- [ ] メインKWで検索した読者の答えが記事内にある
- [ ] 独自の視点や情報が1つ以上ある
- [ ] サービスの弱点・向いていない人が明記されている
- [ ] 断言箇所には根拠（数字・出典）がある
- [ ] 誤字脱字がない
- [ ] スマホ表示を確認した
- [ ] PR表記がファーストビューにある

---

## 15. ブランドボイス

- 「信頼できる先輩」として語りかける
- 具体的な例で説明する
- 根拠とセットで断言する
- 読者の不安に寄り添う
- 「親にすすめられるか？」で判断する

---

## 16. 迷ったときの判断基準

1. これは読者の役に立つか？ → Noなら書かない
2. 根拠はあるか？ → なければ調べるか表現を弱める
3. 自分が読者だったら行動できるか？ → Noなら具体性を足す
4. この記事を身近な人に見せられるか？ → 恥ずかしいなら書き直す
5. 3年後もこの内容で大丈夫か？ → 古くなる情報は更新前提で書く
