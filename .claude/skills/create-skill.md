# create-skill

新しいプロジェクトスキルを作成するスキル。

## 引数
`$ARGS` にスキルの概要が入る（例: `記事の校正チェックをするスキル`、`WordPressのバックアップを取るスキル`）。

## 実行手順

### 1. ユーザーにヒアリング

以下を確認する（明示されていない項目だけ聞く）：

- **スキル名**: 英語のケバブケース（例: `proofread-article`）
- **目的**: このスキルで何を達成したいか
- **入力**: ユーザーが渡す引数（KW、ファイル名、テーマ等）
- **出力**: スキルが生成するもの（ファイル、コマンド、テキスト等）
- **関連ファイル**: 参照すべきドキュメントやスクリプト

### 2. スキルファイルの生成

`.claude/skills/{スキル名}.md` に以下の形式で作成：

```markdown
---
description: 1行の説明文。スキル一覧に表示される。
---

# {スキル名}

（このスキルの目的と概要を1〜2文で）

## 引数
`$ARGS` に◯◯が入る。

## 実行手順

### 1. （最初のステップ）
...

### 2. （次のステップ）
...

## 注意
- 守るべきルール
- エラー時の対処
```

### 3. スキルの品質チェック

作成したスキルが以下を満たしているか確認：

- [ ] description が1行で要点を伝えている
- [ ] 引数の形式と例が明記されている
- [ ] 手順が具体的で曖昧さがない
- [ ] Windows 側の操作が必要なら CLAUDE.md のルール（cd + git pull + 開き方）に従っている
- [ ] 関連ファイルのパスが正確
- [ ] セキュリティルール（CLAUDE.md のセキュリティルール節）に違反していない

### 4. コミット＆プッシュ

```
git add .claude/skills/{スキル名}.md
git commit -m "Add skill: {スキル名} — {1行説明}"
git push origin claude/enable-cocoon-child-cd2DT
```

### 5. 使い方の案内

ユーザーに以下を伝える：
- `/{スキル名}` で呼び出せること
- 引数の渡し方の例
- 関連する既存スキルがあればそれも紹介

## 既存スキル一覧（重複を避ける）

新規作成前に既存スキルと機能が被らないか確認する：

| スキル名 | 用途 |
|---|---|
| new-article | 新記事の作成（KW→構成案→本文→画像） |
| gen-image | 記事画像の生成（HTML/CSS/Playwright） |
| ship-article | 記事のWP反映（画像込みコマンド提示） |
| plan-content | KWから記事選定（優先度付き） |
| teach-me | 初学者モードON |
| create-skill | このスキル自身 |

## 注意

- スキル名は英語ケバブケースで統一（`my-skill-name`）
- 1スキル1目的。複数のことをやるスキルは分割を検討する
- CLAUDE.md のセキュリティルールに違反する操作（exec、eval、秘密情報のハードコード等）を含むスキルは作成しない
